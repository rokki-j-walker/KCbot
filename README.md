# KCbot — бот для Kingdom: Classic

Автономный бот для игры **Kingdom: Classic** (Steam 368230). Играет за короля, управляя им (движение A/D, бег Shift, взаимодействие S). NPC остаются под управлением ИИ игры. Поведение бота эволюционирует: генетический алгоритм подбирает параметры стратегии, ориентируясь на внутриигровые события (сбор монет, строительство, выживание, защита короны).

> [!note] Версия 1.0 — только Python
> Проект полностью на Python. C#-порт движка и WPF-лаунчер удалены,
> график эволюции убран (прогресс показывается в консоли и статусбаре).

## Цель

Максимизировать внутриигровой результат (coins, постройки, выживание, защита от врагов) за фиксированное время эпизода, подбирая параметры поведения короля эволюционным путём. Дополнительно поддерживается обучение на записях игры человека (ручной тренинг), результаты которого подмешиваются в популяцию.

## Как достигается цель

- **Сбор состояния игры.** В `Assembly-CSharp.dll` игры вклеен логгер `KCLog5.dll`, который пишет состояние (монеты, позиция, события) в `kcdbg.txt`. Бот читает хвост файла (256 КБ) и проверяет свежесть: если лог молчит дольше 5 секунд — данные считаются отсутствующими.
- **Управление.** `bot3.py` отправляет нажатия клавиш в окно игры (A/D/Shift/S) через Win32 API. Игра запускается в окне и не захватывает фокус. Режим `--dry` не шлёт ни одной клавиши.
- **Скорость симуляции.** Игра пропатчена: бот пишет множитель в `speed.txt`, игра читает его и меняет `Time.timeScale`. **Потолок — 3×**: на 4× и выше ломаются тайминги игры.
- **Эволюция.** `evo.py` запускает N ботов за эпизод, оценивает их по системе баллов (`bounties.txt`, единая формула `bot3.fitness`) и отбирает лучших (элитизм + кроссовер + затухающие мутации). Результат — `data/best_genome.json`, история — `data/evo_history.json`.
- **Эталонный сейв (baseline).** Перед каждым эпизодом `saves/baseline.dat` восстанавливается в сейв игры — все боты стартуют с одинакового состояния. Если baseline нет, `baseline.py` **сам** запускает игру и доводит её до автосейва.
- **Ручной тренинг.** `human_trainer.py` записывает действия игрока в нескольких сессиях, конвертирует их в геномы (`human_genome_N.json`), которые подмешиваются в популяцию.
- **Сброс.** `--resetAll` удаляет историю, лучший геном, baseline, логи и записи ручного обучения, затем пересоздаёт baseline.

## Структура

```
KCbot/
├── Движок
│   ├── bot3.py              # ядро бота: парсер, решения, ввод, метрики, фитнес
│   ├── evo.py               # эволюция (генетический алгоритм)
│   └── bounties.txt         # 84 ключа весов фитнеса (редактируемый)
├── Лаунчер
│   ├── launcher.py          # GUI (tkinter + sv_ttk): параметры, консоль, темы
│   └── locales/             # ru.json, en.json
├── Пайплайн
│   ├── baseline.py          # автосоздание эталонного сейва
│   ├── human_trainer.py     # ручное обучение на действиях игрока
│   ├── recorder.py          # запись состояния игры в JSON
│   ├── converter.py         # конвертация записи → геном
│   ├── restart.py           # мягкий перезапуск игры (WM_CLOSE)
│   └── hold.py, shot.py     # зажатие клавиши / скриншот
├── Общее
│   ├── gamepath.py          # папка игры, путь сейва, автопоиск Steam
│   └── kc_common.py         # атомарная запись JSON и прочее
├── Инструменты
│   ├── tools/               # KCLog5.dll — рантайм-логгер игры (+ его исходник)
│   ├── patcher.py           # патчинг Assembly-CSharp.dll (чистый Python)
│   ├── dotnet.py            # PE + метаданные .NET (используется патчером)
│   └── assets/              # иконки для сборки
├── Сборка
│   ├── KCbot.spec           # рецепт PyInstaller
│   └── requirements.txt     # зависимости
├── data/                    # геномы, история (создаётся при работе)
├── saves/                   # baseline.dat (создаётся при работе)
└── logs/                    # сессионные логи
```

## Лаунчер (Python)

Графическая оболочка над движком (`tkinter` + `sv_ttk`):

- запуск/остановка обучения, **консоль вывода в реальном времени**: кольцевой буфер (5000 строк), батчинг, авто-скролл, фильтр по уровню (все/предупреждения/ошибки), поиск, очистка, копирование, экспорт в файл;
- все параметры эволюции с валидацией и расчётом ожидаемого времени;
- **папка игры**: ручной выбор, автопоиск (реестр Steam + библиотеки), проверка перед стартом;
- сброс обучения, галочка «Подмешивать ручных ботов в эволюцию»;
- темы оформления, локализация RU/EN с переключением на лету;
- устаревшие значения конфига автоматически приводятся к допустимым диапазонам.

Путь к игре хранится в `%APPDATA%/KCbot/settings.json` (`game_dir`) и передаётся движку через `--game-dir`. Альтернатива — переменная окружения `KCBOT_GAME_DIR`.

## Требования

- Windows 10/11
- Python 3.10+
- Зависимости: `pip install -r requirements.txt` (`sv-ttk`, `Pillow`)
- Kingdom: Classic (Steam 368230), пропатченная для изменения скорости
- Установка через Steam (путь определяется автоматически или указывается вручную)

## Запуск

Через лаунчер: `py launcher.py` → проверить папку игры → «Старт».

Напрямую:
```
py launcher.py
py bot3.py --own-focus --speed 3
py evo.py --pop 50 --rounds 15 --episode 20 --episode-increment 5 --speed 3 --restart
py evo.py --baseline            # создать/восстановить эталонный сейв
py human_trainer.py --sessions 4 --duration 120
py recorder.py --duration 120 --output human_1.json
py evo.py --resetAll --game-dir "C:\...\Kingdom"
```

Горячие клавиши в игре:

| Клавиша | Действие |
|---|---|
| **F8** | пауза / возобновление |
| **F9** | **стоп бота** |
| **F12** | аварийная остановка (бот + игра + обучение) |

## Патч игры

Боту нужен логгер `KCLog5.dll`, вклеенный в `Assembly-CSharp.dll`. Патчер —
чистый Python (`patcher.py` + `dotnet.py`), без C#-инструментов.

```
py patcher.py --status           # пропатчена ли игра
py patcher.py --patch            # пропатчить (спросит про бэкап)
py patcher.py --unpatch          # восстановить бэкап
```

Лаунчер сам проверяет патч при запуске и при изменении скорости.

Что делает патч: вставляет `call KCDbg::Tick()` в начало `Director.Update()`.
Три новые строки метаданных (`AssemblyRef KCLog5`, `TypeRef KCDbg`,
`MemberRef Tick`) добавляются **в конец** своих таблиц, чтобы не сдвинуть
номера строк, на которые ссылается существующий IL; `#~` и `#Strings`
пересобираются и переезжают в секцию `.reloc` (последняя, заканчивается на
EOF — её просто наращиваем); новое тело метода пишется в свободный хвост
секции `.text`. Всё остальное не двигается.

> [!warning] Имя сборки берётся из имени файла
> В папке игры `KCLog5.dll` имеет в манифсте имя `KCLog5_new`. Unity
> резолвит плагины по имени **файла**, поэтому `AssemblyRef` должен быть
> `KCLog5`. При `KCLog5_new` игра выдаёт `FileNotFoundException` и
> `kcdbg.txt` не создаётся.
